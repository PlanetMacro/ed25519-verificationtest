WHAT "IS A FIELD" MEANS HERE (and why)
  The representation is redundant (many limb vectors denote the same field
  element) and machine arithmetic is partial (overflow -> Result monad), so a
  literal `Field FieldElement51` instance is mathematically impossible. The
  theorem is therefore stated the standard way for verified crypto
  implementations, via the denotation
      <<a>> : Fe -> F_p,   <<a>> = (sum_i limb_i * 2^(51 i)) mod p :
   1. F_p IS a field            (mathlib `Field (ZMod P)`, unlocked by an
                                 axiom-free primality certificate for p)
   2. <<.>> is surjective       (every field element has a bounded
                                 representative: encode/denote_encode)
   3. every transpiled op is TOTAL on the documented limb invariant
      (no panic/overflow — including the in-code debug_assert! bounds,
      which survived translation as provable `massert`s) and realizes the
      corresponding F_p operation through <<.>>
   4. hence every field axiom holds for the implementation up to
      denotation — proved as the impl_* corollaries, which run the actual
      transpiled functions:
        impl_add_comm, impl_add_assoc, impl_zero_add, impl_add_neg,
        impl_mul_comm, impl_mul_assoc, impl_one_mul,
        impl_mul_inv_cancel (a != 0), impl_left_distrib, impl_zero_ne_one.

SECURITY FINDINGS
  None — the "break the proof loop" clause was never triggered. Every u64 /
  u128 overflow side condition and both debug_assert!s in the Rust are
  THEOREMS under the documented dalek limb discipline (inputs < 2^54 for
  mul/square/sub/neg; reduce/mul/square re-establish < 2^52).
  Documented caveat (not a finding): pow2k(_, k=0) would wrap k-1 in release
  Rust (debug_assert stripped); unreachable — all in-crate callers pass
  constants >= 1, and the model enforces k >= 1 via the surviving massert.
  Note: the single Rust source change made for extraction (field.rs
  sqrt_ratio_i: conditional_negate -> -& + conditional_assign) is
  semantically identical and constant-time-preserving; crate tests 153/153.
